# Шпаргалка практикантки: сайт и GitHub

Здесь собраны правила и команды, которые понадобятся весь месяц работы над сайтом. Держать открытой рядом с VS Code и сверяться перед каждым новым файлом и каждым коммитом.

Репозиторий `site` остаётся песочницей для тренировок с GitHub. Сам сайт делаем в новом репозитории `my-site`, и там эти правила обязательны с первого коммита.

## 1. Правила имён файлов и папок

Имена пишем латиницей, строчными буквами, без пробелов, слова разделяем дефисом. Браузеры и серверы плохо понимают пробелы и кириллицу в адресах, а на GitHub Pages `Foto.jpg` и `foto.jpg` — разные файлы.

| Так нельзя | Так правильно | Что не так |
| --- | --- | --- |
| `idea site` | `idea` | пробел |
| `идея сайта.txt` | `brief.md` | кириллица, пробел |
| `otchet pp.pdf` | `otchet-pp.pdf` | пробел |
| `Foto_Zavod.JPEG` | `zavod-fasad.jpg` | заглавные, подчёркивание, непонятное имя |
| `О заводе.html` | `about.html` | кириллица, пробел, заглавная |

- Имя должно говорить, что внутри: `ceh-tokarnyj.jpg` лучше, чем `img1.jpg`.
- Главная страница всегда называется `index.html`.
- Расширения тоже пишем строчными: `.jpg`, а не `.JPG`.
- Чтобы видеть расширения, в Проводнике включить: Вид → Показать → Расширения имён файлов.

## 2. Структура папок проекта

На GitHub уходит только папка `site` — это и есть репозиторий. Исходники фото, черновики и документы практики лежат рядом и в Git не попадают.

```
D:\projects\my-site\
├── site\                 ← репозиторий, всё отсюда уходит на GitHub
│   ├── index.html        ← главная
│   ├── about.html        ← о заводе
│   ├── products.html     ← продукция
│   ├── capabilities.html ← наши возможности
│   ├── contacts.html     ← контакты
│   ├── css\
│   │   └── style.css
│   ├── img\              ← только обработанные фото
│   └── README.md
├── photos-original\      ← исходники фото
├── content\              ← черновики текстов
├── docs\                 ← отчёт по практике и другие документы
├── brief.md              ← идея сайта
├── glossary.md           ← словарь терминов
└── journal.md            ← дневник практики
```

- Набор страниц — по своему брифу. Имена выше — пример для сайта завода.
- В VS Code открывать папку `site`: так Live Server и Git работают с нужными файлами.
- Ссылки внутри сайта делать относительными: `css/style.css`, `img/zavod-fasad.jpg`, без `D:\`.

## 3. Команды Git

Каждый вечер — один и тот же цикл. Команды вводятся во встроенном терминале VS Code, в папке `site`.

```
git status
git add .
git commit -m "Добавила страницу контактов"
git push
```

| Команда | Что делает |
| --- | --- |
| `git config --global user.name "Имя"` | Задать имя автора (один раз) |
| `git config --global user.email "почта"` | Задать почту автора (один раз) |
| `git clone <адрес>` | Скачать репозиторий с GitHub |
| `git status` | Показать, что изменилось с последнего коммита |
| `git add .` | Подготовить все изменения к коммиту |
| `git commit -m "..."` | Сохранить снимок изменений |
| `git push` | Отправить коммиты на GitHub |
| `git pull` | Забрать изменения с GitHub |
| `git switch -c new-page` | Создать ветку и перейти в неё |
| `git log --oneline` | Показать историю коммитов |
| `git restore <файл>` | Отменить несохранённые правки в файле |

Сообщение коммита — что сделано, по-русски, одной фразой в прошедшем времени:

| Хорошо | Плохо |
| --- | --- |
| `Добавила меню на все страницы` | `изменения` |
| `Сжала фото цеха до 250 КБ` | `Add files via upload` |
| `Исправила ссылку на контакты` | `123` |

- Один коммит — одно законченное действие. Лучше 3 маленьких коммита, чем 1 большой.
- Файлы добавлять в репозиторий с компьютера через `git add`, `commit` и `push`, а не загрузкой через сайт GitHub.

## 4. Фото и тексты

| Формат | Для чего |
| --- | --- |
| JPG | Фотографии |
| PNG | Графика с прозрачным фоном |
| WebP | Фото для сайта: легче JPG при том же качестве |
| SVG | Иконки и логотипы |

- Ширина фото — не больше 1600 px, вес — до 300 КБ. Сжимать в [Squoosh](https://squoosh.app), пачку файлов — в XnConvert или IrfanView.
- Оригиналы хранить в `photos-original\`, готовые фото — в `site\img\`.
- У каждой картинки должен быть атрибут `alt` с описанием: `<img src="img/ceh.jpg" alt="Токарный цех">`.
- Брать только свои фото или фото с бесплатных стоков: [Unsplash](https://unsplash.com), [Pexels](https://www.pexels.com).
- Тексты писать самой, чужие не копировать. Делать короткие абзацы и подзаголовки, главное ставить в начало.
- Проверять орфографию в LanguageTool или «Орфограммке».

## 5. Работа с нейросетью

**Главное правило:** любой код или текст от нейросети нужно уметь объяснить своими словами. Не можешь объяснить — не вставляй. Пароли, личные данные и рабочую информацию в нейросеть не отправлять.

| Задача | Шаблон запроса |
| --- | --- |
| Объяснение | «Объясни, что такое [термин], как новичку, на бытовом примере, в 5 предложениях» |
| Код | «Я делаю сайт на HTML и CSS без фреймворков. Напиши [что нужно] и объясни каждую строку комментарием» |
| Ошибка | «Вот мой код [код] и вот что пишет браузер [ошибка]. Почему так и как исправить?» |
| Текст | «Отредактируй текст для сайта: короче, проще, без канцелярита. Смысл не меняй. Покажи, что изменил» |
| Проверка себя | «Задай мне 5 вопросов по теме [тема], чтобы проверить, поняла ли я» |

Подойдут GigaChat, Алиса или DeepSeek.

## 6. Каждый день

Работа идёт самостоятельно, но каждый день, а не одним вечером в неделю.

1. Днём — 4–5 часов работы над сайтом.
2. Вечером — коммит и пуш на GitHub: по ним видно, что работа идёт.
3. Вечером — 3 строки в `journal.md`: что сделала, что не получилось, какой вопрос остался.

Если застряла — сначала спросить нейросеть по шаблону выше, потом написать вопрос в `journal.md` или руководителю.

Пример записи в `journal.md`:

```
## 29.10
Сделала: шапку с меню на главной.
Не получилось: меню не встаёт в строку на телефоне.
Вопрос: как сделать меню-«бургер»?
```
